# Требования FinFlow 2.0

Требования описывают поведение приложения в версии 2.0. У каждого есть идентификатор — по нему тест-кейсы и автотесты связаны с требованиями в [матрице покрытия](traceability.md).

Приоритет: **P1** — без этого приложение бесполезно, **P2** — важная функция, **P3** — удобство.

## Операции

| ID | Требование | Приоритет |
| --- | --- | --- |
| REQ-01 | Пользователь добавляет операцию: тип (расход или доход), сумма, категория, дата, комментарий. | P1 |
| REQ-02 | Сумма — число больше 0 и не больше 1 000 000 000 ₸, не больше двух знаков после запятой. Разделитель дробной части — запятая или точка, пробелы между разрядами допускаются. | P1 |
| REQ-03 | Дата обязательна и не может быть позже сегодняшнего дня. По умолчанию подставляется сегодняшняя дата. | P1 |
| REQ-04 | Комментарий необязателен, не длиннее 80 символов. Текст отображается как есть, HTML не выполняется. | P1 |
| REQ-05 | Список категорий зависит от типа: 8 категорий расходов и 4 категории доходов. | P2 |
| REQ-06 | Ошибка ввода показывается под формой, поле с ошибкой подсвечивается; сообщение исчезает, когда пользователь исправляет поле. | P2 |
| REQ-07 | Операцию можно изменить: форма переходит в режим редактирования, «Сохранить» применяет изменения, «Отмена» и Escape отменяют их. | P2 |
| REQ-08 | Операцию можно удалить; в течение 5 секунд её можно вернуть кнопкой «Вернуть» в уведомлении. | P2 |
| REQ-09 | После добавления или изменения операции открывается её месяц, фильтры, которые её скрыли бы, сбрасываются. | P3 |
| REQ-10 | Операции, бюджеты, тема и язык сохраняются в браузере и остаются после перезагрузки. | P1 |

## Месяц и итоги

| ID | Требование | Приоритет |
| --- | --- | --- |
| REQ-11 | По умолчанию открыт текущий месяц. Можно перейти к прошлым месяцам; переход в будущий месяц недоступен. | P2 |
| REQ-12 | Итоги месяца: доходы, расходы и остаток (доходы минус расходы). Отрицательный остаток показывается с минусом красным цветом. | P1 |
| REQ-13 | Расходы сравниваются с прошлым месяцем в процентах. Если текущий месяц ещё идёт, сравнение идёт с теми же днями прошлого месяца. Если в одном из месяцев расходов нет, сравнение не показывается. | P3 |
| REQ-14 | Суммы отображаются в тенге по правилам выбранного языка: «12 500 ₸» по-русски, «₸12,500» по-английски; дробная часть — только если есть тиыны, и всегда двумя цифрами. | P2 |

## Аналитика

| ID | Требование | Приоритет |
| --- | --- | --- |
| REQ-15 | Кольцевая диаграмма показывает расходы месяца по категориям с долей в процентах. | P2 |
| REQ-16 | Клик по сектору диаграммы или строке легенды показывает в списке только операции этой категории; повторный клик или «Показать все» снимает фильтр. | P2 |
| REQ-17 | Бюджет — лимит расходов по категории на месяц. Статус: до 80 % — норма, от 80 % до 100 % включительно — предупреждение, больше 100 % — перерасход с суммой превышения. | P2 |
| REQ-18 | Лимит бюджета — целое число тенге или пустое поле (лимита нет). Неверное значение не сохраняется, показывается ошибка. | P2 |
| REQ-19 | График показывает доходы и расходы за 6 месяцев, заканчивая текущим. Клик по месяцу открывает его. | P3 |

## Импорт и экспорт

| ID | Требование | Приоритет |
| --- | --- | --- |
| REQ-23 | Экспорт операций месяца в CSV: разделитель «;», кодировка UTF-8 с BOM, имя файла `finflow-ГГГГ-ММ.csv`. Кнопка недоступна, если в месяце нет операций. | P2 |
| REQ-24 | Импорт CSV, выгруженного из FinFlow на любом языке. Строки с ошибками (несуществующая дата, дата в будущем, неизвестный тип или категория, неверная сумма) пропускаются; Операции, которые уже есть в приложении (совпадают дата, тип, категория, сумма и комментарий), не добавляются повторно; одинаковые строки внутри одного файла сохраняются. Пользователь видит, сколько операций загружено, сколько уже было и сколько строк пропущено. | P2 |
